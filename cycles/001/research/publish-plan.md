# Publication reconciliation plan

Stage: distillation. Analysis kind: **exploratory**. No new experiment is proposed.

The project goal is verified engineering completion with reproducible artifacts, regardless of effect direction. The subgoal is a bounded final synthesis ready for controller publication. The immediate objective is to reconcile README, reproduction docs, claims, requirements and final report with the preserved results and substantive review.

Expected learning: whether publication documents agree with the accepted measurements and whether packaging drift remains. Estimated effort: a short documentation pass and inexpensive non-fitting consistency checks. Reusing saved predictions, protected-file hashes and review evidence has greater information value here than another fit; retraining would change the evidence without resolving a documentation defect. Switching to a new architecture, coefficient search or evaluation set is outside this phase.

Predictions before checks:

- Protected fixture, protocol, registration, result and checkpoint bytes should match the saved review audit. A mismatch falsifies the no-drift expectation and requires investigation before handoff.
- Recomputing the registered paired summary should reproduce the saved inconclusive tie. A mismatch would support an aggregation or artifact error rather than the current interpretation.
- Claim references and requirement paths should resolve. README and docs may retain historical phase wording; such wording can be repaired without changing results.
- Final paper copies, saved site records and local publication links should agree. A discrepancy would support a packaging defect; successful checks would still not establish deployed-page or browser visual correctness.

Competing explanations: genuine local accuracy insensitivity despite changed parameters; duplicated or changed artifacts; scoring/aggregation bugs; stale prose or generated status snapshots. Existing controls and audits constrain specified implementation alternatives without proving absence of every bug or leakage class.

Selection rationale: finish the fixed study with precise claims and explicit residual limits. Preserve source/protocol histories, all negative results, initial review failures and controller ownership of publication. No training, new model call, collaborator, Git mutation or upload is authorized in this phase. Record actual observations and lessons in reports/final.md after the checks.
